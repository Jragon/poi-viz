**A) V1 Motion Model (As Designed)**
V1’s mental model is: each hand is two linear oscillators in beat-time, then projected into Cartesian space.

1. Arm channel is absolute angle over time.
2. Poi channel is relative angle over time.
3. Head angle is composed as `arm + relative`.
4. Hand and head positions are then generated by polar-to-Cartesian conversion and vector addition.

Phase, frequency, and offsets are encoded as constant coefficients in linear angle equations (`speed * t + phase`) per hand and per channel. Time is in beats, so tempo changes affect real-time playback speed but do not change the beat-domain geometric pattern definition.

Multi-oscillator interaction happens by coupling:

1. Left and right arms interact through phase and sign relationships.
2. Left and right heads inherit that plus the relative poi channels.
3. VTG classification later reads those relationships, but the engine itself stays continuous and purely parametric.

So V1 is fundamentally “continuous oscillator fields in Cartesian output space,” not “explicit pose segments.”

**B) Why Cartesian Parametric Motion Breaks Down for Sequencing**
The core issue is not numerical math quality; it is control topology.

1. Boundaries are not native objects.
   V1 produces a continuous function over all time. Segment starts/ends are external decisions imposed later, not first-class in the model.

2. Transitions are not first-class semantics.
   You can switch parameters at time `t`, but that does not define transition intent. Continuity, direction preservation, and loop seam behavior must be inferred or patched.

3. Continuity constraints are implicit and fragile.
   To keep boundary continuity, you must solve for compatible phases from propagated end angles. That logic lives outside base motion equations, which means continuity is extra machinery, not intrinsic structure.

4. Sequencing becomes math-heavy instead of structural.
   Author intent becomes “solve and constrain oscillator coefficients” rather than “compose named movement units.” The sequencing layer in `/Users/rory/code/poi/src/vtg/sequence.ts` shows this clearly: boundary computation, snap grids, propagated start angles, sign constraints, fallback inversion logic.

In short: V1 is excellent at generating smooth motion, but weak at declaring and composing discrete phrases.

**C) The Emergence of “Circle Speed” as a Patch**
“Circle speed” in your framing corresponds to the system’s explicit absolute head-speed abstraction (`h`) in V1 (`/Users/rory/code/poi/src/state/speedUnits.ts`, `/Users/rory/code/poi/src/components/controls/ControlsHandPanel.vue`).

Conceptually it represents:

1. A poi-centric angular control in world frame.
2. A more intuitive handle than raw relative speed for many spinner mental models.

Problem it solved:

1. Raw relative speed (`r`) is mathematically clean but cognitively indirect.
2. Users think in visible head rotation/circle behavior.
3. So V1 exposes `h` and internally solves `r = h - a`.

How it reintroduced angular thinking into Cartesian-first design:

1. It effectively re-centers control around absolute rotational behavior.
2. That is closer to node/angle semantics than pure Cartesian function tuning.

What complexity it added:

1. Two speed vocabularies (`relative` and `absolute`) with conversion invariants.
2. Additional UI/state logic to keep channels coherent.
3. More classification/interpretation burden when sequencing or constraining direction changes.

So “circle speed” is not a mistake. It is a structural symptom: the system needed an angular-authoring abstraction that the base model did not natively prioritize.

**D) Comparison: Parametric Cartesian vs Circular Node**
| Axis | V1 Parametric Cartesian | Circular Relative Node System |
|---|---|---|
| Cognitive load | High for composition; users reason via coefficients and derived effects | Lower; users reason via explicit node angles/velocities/relations |
| Composability | Continuous functions compose mathematically, but phrase composition is awkward | Segment/node composition is natural and explicit |
| Boundary definition | External/derived from playhead math | Native: boundaries are explicit segment/node states |
| Sequencing | Retrofitted via continuity solvers and constraints | First-class: scheduling discrete segments is core |
| Partial evaluation | Hard: function meaning depends on global time and coefficient context | Easy: evaluate one segment/node locally |
| Continuity constraints | Implicit, solved post hoc | Explicit contract between segment end/start poses |
| Spinner intuition | Indirect unless patched (e.g., head/circle speed controls) | Direct mapping to angular mental model |

Narrative: V1 optimizes for continuous deterministic generation; node systems optimize for authored structure and sequence semantics. If the product goal is sequencer-first authoring, the node model is the lower-friction foundation.

**E) What V1 Does Well (To Keep)**

1. Deterministic engine contracts are strong and clean.
   The engine equations and sampling behavior are explicit and test-backed (`/Users/rory/code/poi/tests/engine/invariants.test.ts`, `/Users/rory/code/poi/tests/engine/sampling.test.ts`).

2. Separation of concerns is solid.
   Engine math, state utilities, VTG relations, and rendering are intentionally separated and lint-guarded.

3. Beat-domain time model is correct for music-synchronous motion.
   Transport converts seconds to beats, while motion stays beat-native.

4. Useful invariant vocabulary exists.
   `arm`, `relative`, `head`, plus identities like `head = arm + rel` and tether/arm radius invariants are valuable and reusable.

5. Visualization layer is conceptually sound.
   Pattern view plus oscillator wave view is a strong dual representation for debugging and teaching motion behavior.

**F) What V1 Makes Hard or Impossible**

1. First-class phrase transitions are disproportionately hard.
   Architectural cause: motion is global continuous function, not piecewise state graph.

2. Authoring boundary semantics (“what should happen exactly at segment switch?”) is structurally awkward.
   Architectural cause: boundaries are post-processed through continuity propagation instead of represented directly.

3. Direction constraints across segments require compensating logic.
   Architectural cause: sign behavior is emergent from combined channels, so sequence layer must inspect and patch flips (`allowPoiDirectionFlip`, fallback inversion).

4. Complexity scales non-linearly with sequence length and constraints.
   Architectural cause: each new segment introduces propagation dependencies and constraint interactions, not just additive local data.

5. “Intuitive controls” tend to reappear as derived abstractions.
   Architectural cause: base parameterization is mathematically compact but not aligned with how users think about angular movement units.

**G) Lessons Distilled for V2**

1. Design rules.

- Boundaries must be explicit data, not inferred math events.
- Sequencing must be piecewise-first, not continuous-function-first.
- Pose representation and scheduling must be separate concerns.
- Continuity policies must be explicit and testable at seams.
- User-facing controls should match spinner mental primitives directly.

2. Justification.

- Piecewise-first sequencing: because phrase boundaries are product semantics, not incidental timestamps.
- Circular node rig representation: because motion authoring is angular/relational in practice, and V1 repeatedly had to reintroduce that abstraction.
- Separate pose from schedule: because continuity, looping, and transport concerns should not mutate underlying pose semantics.

3. Risks to watch in V2.

- Recreating hidden derived channels that obscure authored intent.
- Letting transport/playback rules leak into pose definitions.
- Allowing multiple competing continuity policies without explicit selection.
- Reintroducing implicit global-time coupling that makes local segment reasoning hard.

**H) V1 → V2 Conceptual Migration Map**
| V1 Concept | V2 Equivalent | Rationale |
|---|---|---|
| Global parametric `x(t), y(t)` from oscillator coefficients | Node rig pose evaluated per segment | Makes boundaries and local reasoning explicit |
| Continuous whole-loop function | Piecewise segment timeline | Sequencing becomes structural, not coefficient-solving |
| `arm + relative -> head` implicit channel coupling | Explicit per-node angular channels | Keeps angular intent first-class |
| Derived “absolute head speed / circle speed” patch | Native explicit angular velocity per node | Removes conversion indirection |
| Boundary continuity solved post hoc | Boundary continuity contract between segments | Makes seam behavior declarative and testable |
| Sequence constraints as runtime fallback patches | Authored transition rules in schedule layer | Reduces hidden corrective behavior |
| Global-time dependence for meaning | Local segment semantics + schedule composition | Enables partial evaluation and modular editing |
| VTG relation extraction from continuous state | VTG-compatible descriptors attached to segments/nodes | Preserves relation language while improving composition |

Net conclusion: V1 proves deterministic motion math and visualization quality. It also shows that sequencer-grade authoring demands explicit piecewise structure and angular node primitives. That makes V2’s piecewise-first, node-based direction a direct architectural consequence, not a stylistic rewrite.
